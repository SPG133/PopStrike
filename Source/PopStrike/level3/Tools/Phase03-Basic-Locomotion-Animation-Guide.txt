PopStrike 阶段 03：基础联网角色动画搭建指南
================================================

适用项目：D:\Unreal Projects\PopStrike
适用引擎：本机源码版 Unreal Engine 5.8.2
本阶段范围：Idle、四方向移动、跳起、下落、落地、蹲伏
本阶段不做：武器分层、瞄准偏移、脚部 IK、转身、跨栏、攀爬、Motion Matching


一、这套方案采用什么成熟经验
--------------------------------

这套实现采用成熟联网角色系统普遍使用的职责分离：

1. CharacterMovementComponent（CMC）负责真实位置、速度、跳跃、蹲伏、碰撞和网络移动。
2. Character/PlayerController 负责玩法输入和是否允许移动。
3. AnimInstance 只采样 Character/CMC 已经确定的状态。
4. Animation Blueprint 只负责选择姿势、混合和播放表现。
5. 普通移动使用 In-Place 动画；一次性特殊移动才考虑 Root Motion Montage。
6. 不用 Anim Notify 决定角色已经落地、已经爬上平台或已经移动到某处。
7. 不用客户端 Timeline/SetActorLocation 驱动联网角色移动。

这和 Epic 官方 Lyra 的核心边界相同：玩法状态提供事实，AnimBP 消费数据并负责表现。
PopStrike 当前只有六人，不照搬 Lyra 的完整 Linked Anim Layer、Chooser、Motion Matching
和大型数据体系。先用一个小型状态机建立稳定基线，再按真实需求扩展。

二、本阶段最终数据流
--------------------

玩家输入
  -> APSMatchPlayerController
  -> APSFPSCharacter / CharacterMovementComponent
  -> CMC 产生真实 Velocity、MovementMode、bIsCrouched
  -> UPSAnimInstance 每帧读取这些结果
  -> ABP_FPSCharacter 根据变量选择动画
  -> 其他客户端也根据已复制的角色移动状态播放相同类型动画

基础移动不增加动画 RPC，也不复制 Speed、ForwardSpeed、RightSpeed。
这些值由每台机器从已经同步的 Character 状态计算，避免重复网络数据。

六、第二步：给 C++ 增加垂直速度
--------------------------------

为什么需要：当前 bFalling 只能说明角色离地，不能区分向上跳和向下落。

文件：
D:\Unreal Projects\PopStrike\Source\PopStrike\level3\PSAnimInstance.h

在其他 Locomotion 变量附近增加：

UPROPERTY(BlueprintReadOnly, Category="Locomotion")
float VerticalSpeed = 0.f;

文件：
D:\Unreal Projects\PopStrike\Source\PopStrike\level3\PSAnimInstance.cpp

在 NativeUpdateAnimation 中，读取角色速度后增加：

VerticalSpeed = Character->GetVelocity().Z;

最终含义：
- VerticalSpeed > 0：角色向上
- VerticalSpeed 接近 0：到达跳跃最高点
- VerticalSpeed < 0：角色下落

只增加这一个变量。暂时不要添加复杂的 Acceleration、Lean、FootIK 数据。

关闭 Unreal Editor 后编译：

  "-Project=D:\Unreal Projects\PopStrike\PopStrike.uproject" `

十、第六步：设置状态转换规则
--------------------------------

Entry -> Grounded

Grounded -> Crouched：
bCrouching == true AND bFalling == false
Blend Duration = 0.15

Crouched -> Grounded：
bCrouching == false AND bFalling == false
Blend Duration = 0.15

Grounded -> JumpStart：
bFalling == true AND VerticalSpeed > 0
Blend Duration = 0.08

Crouched -> JumpStart：
仅当你允许蹲伏状态跳跃时建立：
bFalling == true AND VerticalSpeed > 0

JumpStart -> Falling：
VerticalSpeed <= 0
OR
JumpStart 动画的 Time Remaining Ratio < 0.1

Falling -> Landing：
bFalling == false
Blend Duration = 0.05

Landing -> Grounded：
Time Remaining Ratio < 0.1 AND bCrouching == false

Landing -> Crouched：
Time Remaining Ratio < 0.1 AND bCrouching == true

不要让 Anim Notify 修改 bFalling。bFalling 必须始终来自 CharacterMovementComponent。

十四、第二轮验收清单（联网）
--------------------------------

正式结论至少使用 Dedicated Server + 两个客户端；条件暂不具备时可以先用 PIE 两玩家。

客户端 A 操作，客户端 B 观察：

1. A 前后左右移动，B 看到正确方向动画。
2. A 跳跃，B 不长期卡在 Falling。
3. A 蹲伏，B 的胶囊高度和动画一致。
4. A 快速切换方向，B 不出现持续滑步或 T Pose。
5. 不需要为基础动画添加 Server/Multicast RPC。
6. 模拟延迟后，动画可以有轻微平滑延迟，但位置不能被动画拖离胶囊。

如果基础移动动画需要额外 RPC 才能同步，先检查 AnimBP 是否读取了 CMC/Character 状态，
不要直接增加动画广播 RPC。


十五、常见错误与定位
--------------------

问题：角色一直 T Pose
检查：BP_FPSCharacter 的 Anim Class、ABP Skeleton、ABP 是否编译成功。

问题：W 播放后退动画
检查：Blend Space 的 Vertical Axis 正负方向是否放反。

问题：A/D 放反
检查：RightSpeed 轴和 Left/Right 样本位置。

问题：角色移动但动画仍 Idle
检查：ABP Parent Class 是否为 PSAnimInstance；运行时 Debug Filter 是否选对实例。

问题：跳起来一直保持 JumpStart
检查：是否已经添加 VerticalSpeed；JumpStart -> Falling 是否允许 Time Remaining 兜底。

问题：落地后卡住
检查：Landing 动画 Loop 必须关闭；Landing 出口使用 Time Remaining Ratio。

问题：模型移动方向正确但脚底滑动
第一阶段允许少量滑步。先确认 MaxWalkSpeed=450 和动画节奏大致匹配，后续再加入
Stride Warping/Distance Matching；不要为了脚步完全贴合修改真实网络移动速度。

问题：本地看不到角色动画
原因：当前世界 Mesh 设置了 Owner No See；使用第二客户端观察。

问题：胶囊移动但 Mesh 离开胶囊
检查：普通动画不要启用 Root Motion；AnimBP 使用 Root Motion from Montages Only。

十七、进入攀爬阶段的门槛
------------------------

必须先满足：

- 单客户端全部基础状态正确。
- 第二客户端能看到正确的移动、跳跃、蹲伏动画。
- 动画不会改变角色权威碰撞位置。
- 没有长期卡状态。
- ABP_FPSCharacter 是唯一主 AnimBP。

通过后再开始 Traversal：

1. C++检测前方障碍、顶部和目标胶囊空间。
2. 按高度分为 Vault、Mantle、Reject。
3. 服务器从权威位置重新验证。
4. Vault/Mantle 使用 Root Motion Montage。
5. 使用 Motion Warping 对齐真实障碍目标。
6. 动作状态包含类型、序号、服务器起始时间、目标 Transform。
7. 攀爬期间禁止普通移动、开火和换弹。
8. 动作完成后恢复 CMC Walking。
